# Spec 01: Project Setup

**Branch:** `feature/project-setup`
**Product spec:** `docs/product/v1.md` §14 (roadmap row 01), §4 (navigation — only to name the route groups)
**Plan mode:** required — adds dependencies, creates far more than ~5 files, and initialises Supabase (config that CI picks up automatically).
**Status:** ✅ Shipped

## Overview
After this ships there is a runnable, empty LikeToOrder app: `npx expo start` opens a single placeholder screen styled from theme tokens, the Supabase client and react-query are wired up, the local Supabase project is initialised, and `npm run lint`, `typecheck`, `test` and `db:types` all work and pass in CI. It comes first because every later feature depends on the toolchain, the token file, the base `ui/` components and the Supabase client. No product features, tables or auth are built here.

## User stories
- As the developer, I can clone the repo, run `npm install` and `npx expo start`, and see the app boot on a simulator so that every later feature starts from a working base.
- As the developer, I can run lint, typecheck, tests and `db:types` with one command each so that quality gates are the same locally and in CI.
- As the developer, I can import colors, spacing, radius and type sizes from one tokens file so that no screen hardcodes styling.
- As the developer, I can import a typed Supabase client and a configured react-query client so that feature `api.ts` and hooks files have a single place to build on.

## Screens & routes
- `app/_layout.tsx` — root layout: wraps the app in `QueryClientProvider`, `SafeAreaProvider`, and renders the `Stack`/`Slot`. — public
- `app/index.tsx` — placeholder home screen ("LikeToOrder" title, one line of text, one `Button` demonstrating the base components). Replaced by auth and tabs in specs 02–03. — public

The `(auth)` and `(tabs)` route groups are NOT created here (specs 02 and 03).

## Database changes
No database changes. `npx supabase init` creates `supabase/config.toml` only; `supabase/migrations/` stays empty (with `.gitkeep`) and `supabase/seed.sql` is an empty file with a one-line comment.

Because `supabase/config.toml` now exists, CI starts running the database steps (`supabase db start`, `db reset`, `test db`, types diff). Those must pass on an empty schema — see Decisions 3 and 4.

## Components & hooks
- `src/theme/tokens.ts` — `colors`, `space`, `radius`, `type` exactly as in the liketoorder-ui skill; named exports. Extended with `weight` (font weights) and `size.touch` (44pt minimum touch target) so components need no literals.
- `src/theme/useTheme.ts` — returns the token set (light only for now) so screens read colors through a hook and dark mode can be added later.
- `src/components/ui/Screen.tsx` — safe-area container with `bg` background.
- `src/components/ui/Text.tsx` — variants `caption | body | bodyLg | title | h1`, color from theme.
- `src/components/ui/Button.tsx` — variants primary/secondary/ghost, `loading` and `disabled` states, min height 44, requires `accessibilityLabel` (defaults to the title) and sets `accessibilityRole="button"`.
- `src/components/ui/Card.tsx` — surface container with border and radius.
- `src/components/ui/EmptyState.tsx` — friendly line + optional action button.
- `src/components/ui/ErrorState.tsx` — message + required Retry button.
- `src/components/ui/Skeleton.tsx` — loading placeholder; no looping animation in this spec (a static block), so reduce-motion is not yet a concern.
- `src/components/ui/index.ts` — barrel of the above (named re-exports).
- `src/lib/supabase.ts` — `createClient<Database>` using `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY`; session persisted via `@react-native-async-storage/async-storage`; throws a clear error at startup if either env var is missing. Anon key only, never `service_role`.
- `src/lib/queryClient.ts` — shared `QueryClient` with sensible defaults (e.g. retry once, 30 s stale time).
- `src/lib/env.ts` — reads and validates the two `EXPO_PUBLIC_*` vars with zod (zod is already in the stack; it is a dependency here, see below).
- `src/types/database.ts` — GENERATED by `npm run db:types` from the empty local schema; never hand-edited.

Not created here (later specs add them with their features): `Sheet`, `FlagIcon`, `Chip`, `StatusChip`, `Avatar`, `TextField`. See Decision 1.

## Rules for implementation
Always include:
- RLS on every new table + pgTAP test (no tables in this spec)
- Supabase calls only in `src/features/<x>/api.ts` (`src/lib/supabase.ts` is the client only; no queries)
- Theme tokens only, no hardcoded colors/sizes
- Loading / empty / error / success states on every screen (the placeholder screen is static; `EmptyState`, `ErrorState`, `Skeleton` exist for later screens)
- Accessibility labels on every touchable
Feature-specific rules:
- Expo managed with CNG: do NOT run `expo prebuild` into the repo; no `ios/` or `android/` committed.
- TypeScript strict; no `any`; named exports (default exports only where expo-router requires them for route files).
- npm scripts exactly: `start`, `lint`, `typecheck` (`tsc --noEmit`), `test` (`jest`), `db:types` (`supabase gen types typescript --local > src/types/database.ts`), plus `ios`/`android` from the template.
- `npm run lint` must pass with zero warnings treated as errors (`--max-warnings 0`).
- Never read or edit `.env`; the app reads env through `src/lib/env.ts`. For local verification, ask Archan to create `.env` from `.env.example`.
- Do not touch `.github/workflows/*` beyond the Supabase CLI version pin in `ci.yml`, unless CI fails because of this spec's output; if so, explain the change in the PR.
- Do not install anything outside the New dependencies list above.
- Run `npm run db:types` only with local Supabase running (needs Docker); if Docker is unavailable, stop and tell Archan rather than hand-writing the file.

## Definition of done
- [x] `npm install` on a fresh clone succeeds and `package-lock.json` is committed.
- [x] `npx expo start` boots; the placeholder screen renders on an iOS simulator (or Expo Go) with no red-screen or yellow-box warnings.
- [x] `npm run lint` exits 0 with `--max-warnings 0`.
- [x] `npm run typecheck` exits 0 under `strict: true`.
- [x] `npm test` exits 0; tests cover `Button` (renders title, fires `onPress`, blocked when `loading`/`disabled`, has role `button` and an accessibility label), `ErrorState` (Retry calls handler), `EmptyState` (action optional), and `env.ts` (throws with a clear message when a var is missing, returns values when present).
- [x] `npx supabase start` succeeds locally and `npm run db:types` produces `src/types/database.ts` with no hand edits.
- [x] `npx supabase db reset` and `npx supabase test db` succeed on the empty schema (no migrations).
- [x] No hardcoded hex colors, pixel spacing or font sizes outside `src/theme/tokens.ts` (checked by grep in review).
- [x] Every interactive `ui/` component sets `accessibilityRole` and `accessibilityLabel`, and `Button` hit area is ≥ 44pt.
- [x] `src/lib/supabase.ts` uses only the anon key; grep for `service_role` in the repo returns nothing outside docs and comments.
- [ ] The GitHub CI workflow is green on the PR (app checks and database checks both run).
- [x] `ios/` and `android/` are not committed; `.env` is not committed.
- [x] Missing `EXPO_PUBLIC_SUPABASE_URL` or `EXPO_PUBLIC_SUPABASE_ANON_KEY` produces a clear startup error (not a silent undefined).

3. **pgTAP on an empty schema:** add the trivial smoke test `supabase/tests/00_smoke.test.sql`; replace it once spec 02 adds real RLS tests.
4. **Generated types on an empty schema:** commit `src/types/database.ts` generated by `npm run db:types` from the empty schema.
5. **Supabase CLI:** `supabase` as an exact-pinned devDependency, and `ci.yml` makes `setup-cli` use the same version as `package.json`.
6. **EAS:** leave the EAS project ID unset; Archan adds `EXPO_TOKEN` / staging secrets later.
7. **Node:** `engines.node >=22` in `package.json` and `.nvmrc` with `22`.
